# 本地实时看板（Dashboard）

按**当前调研任务动态生成**的本地 HTML 看板：结构随场景与本轮数据组装，文案随话题写入，**禁止套用一份固定成品页**。无服务端、无账号、无外链；`research.md` 仍是唯一事实源，看板是「可读的态势页」，必须有足够文字解读与预测，而不是只有数字卡片。

## 触发与形态

| 时机 | 动作 |
|------|------|
| 监测方案确认时 | 可勾选「开启本地看板」（默认否） |
| **首轮完整报告输出后** | **必须询问一次**：是否切换为实时看板模式 |
| 用户主动要求 | 立即开启或刷新生成 |

询问话术：

> 本轮调研已完成。是否开启**本地实时看板**？开启后会在话题目录**按本话题场景与本轮结论动态生成** `dashboard/index.html`（含文字解读与预测），浏览器直接打开即可；之后每轮采集会重写数据并刷新解读。

- 同意 → 按下文生成看板，写入 `dashboard: on`
- 拒绝 → 不生成；后续可随时开启

## 生成原则（动态，非固定模板）

1. **先读 research.md，再决定画什么**：模块列表由「场景 + 本轮实际有数据的维度 + 预警」决定；无数据模块不进页面（不写空壳标题）
2. **标题、标签、竞品名、KMI 名全部写成本话题的**，禁止残留占位符 `{产品}` 或他话题名称
3. **文字优先于图表**：每个数字旁必须有一句「意味着什么」；预测、信号、缺口、下轮计划必须是完整中文段落，不是标签堆
4. **每轮可改结构**：新出现竞品/新启用 KMI/触发危机 → 增删模块并重新生成 HTML；仅数字变化则可只重写 `data.js`
5. **参考骨架不是交付物**：`references/dashboard_template.html` 仅供对照信息架构与渲染写法；交付的是本话题自己的 `dashboard/index.html`

## 目录与职责

```
~/.local/share/data-research/{topic-id}/
├── research.md
└── dashboard/
    ├── index.html    # 每话题动态生成（结构+文案贴合本任务）
    └── data.js       # 结构化数据与长文案字段，每轮重写
```

- 生成 `index.html` 时写入：本话题标题、模块顺序、场景注解、页脚免责声明
- 每轮更新顺序：**research.md → data.js → 若模块有变则重生成 index.html → 否则只刷 data.js**
- 无外链、无构建；`file://` 可打开。自动刷新为页面每 30s 重载 data.js（file:// 受限时顶栏提示手动刷新）

## data.js 契约（丰富文案版）

```js
window.__TOPIC__ = { /* 见下 */ };
```

长文案字段用 **段落数组**（每项一段，视图逐段渲染），禁止把整页解读压成一行标题。

### 顶层

| 字段 | 说明 |
|------|------|
| `meta` | 话题元信息 |
| `summary` | 态势总览：headline + 多段解读 |
| `logic` | 本轮分析逻辑（为何选这些维度、基准、样本） |
| `kpi` | 指标卡（含 status / n / delta / note 一句解读） |
| `sentiment_series` | 按轮演变 |
| `findings` | 核心发现（title + detail 段落 + implication） |
| `interpretation` | 「意味着什么」总解读段落 |
| `signals` | 信号与建议 |
| `predictions` | 预测（结论/触发/跟踪/置信） |
| `risks` | 风险矩阵行 |
| `competitors` | 对标（可选） |
| `platform_notes` | 各平台评论区文字摘要 |
| `alerts` | 预警记录 |
| `gaps` | 缺口 |
| `next_plan` | 下轮补采计划（段落） |
| `catalysts` | 催化剂/日历（可选） |
| `timeline` | 演变节点简表 |

### 文案硬约束

1. `summary.body`、`interpretation`、`predictions[].body`、`signals[].action`、`platform_notes[].text`、`next_plan` **必须是完整中文句子**，读者不打开 research.md 也能懂
2. 每条预测必须有：结论 + 触发条件 + 跟踪指标；禁止「视情况而定」式空话
3. 数字必须带 `n=`；`n<30` 的项写进文字观察，不进 KPI 卡
4. 不把 research.md 原始数据条成段粘贴；看板是编辑过的「可读层」
5. 投资/金融页脚：「信息线索，不构成投资建议」

## 每轮更新协议

在写完 research.md 之后：

1. 按契约重写 `data.js`（含全部长文案字段）
2. 对照模块选择表：若场景/维度/预警集合变化 → **重新生成** `index.html`；否则沿用
3. 首次开启：从零生成 `index.html` + `data.js`（可参考骨架的信息架构，**必须替换全部文案与模块集合**）
4. 报告末尾附一句：本地看板已更新路径

禁止：

- 复制一份与话题无关的通用看板交差
- 只写数字不写解读
- 为看板单独再采一轮
- 外链字体/图表库

## 信息架构（生成时遵守的骨架）

```
顶栏：话题名 · 场景 · 第 N 轮 · 更新时间 · 状态
├─ 态势总览（headline + 3–6 段 body）
├─ 本轮分析逻辑
├─ KPI 行（每卡一句 note）
├─ 双栏：
│   ├ 情绪/声量演变 + 阶段注解
│   └ 预警 / 信号与建议（含 action）
├─ 核心发现列表（detail + implication）
├─ 意味着什么（interpretation 段落）
├─ 预测与触发条件（卡片：结论/置信/触发/跟踪）
├─ 风险矩阵表（按需）
├─ 竞品（按需）
├─ 平台评论区文字摘要
└─ 缺口 + 下轮计划
```

视觉保持内部情报台风格：浅底、信息条、左侧状态色条、等宽字体承载数字与时间；不靠插画装饰，靠版式和文案密度。

## 骨架文件

[dashboard_template.html](dashboard_template.html) = **生成参考**（结构 + 渲染写法 + 演示数据）。  
交付时必须生成话题自己的 `index.html`；骨架中的演示品牌、章节开关仅作说明。

## 边界

- 看板频率 = 采集频率，不是秒级实时
- 不推送、不装服务、不替代标准报告
- 金融场景保留免责句
