## 数据条目行格式

固定前缀 + 可选扩展字段。一行一条，禁止把多条评论塞进一行。

```
- [{ISO时间}] [{来源}] [{情感}] [{类型}] [{互动}] [{采集方式}] id={content_id} {url} 内容摘要…
```

| 槽位 | 取值 |
|------|------|
| 时间 | ISO8601，采集/发布时间戳，禁止占位 |
| 来源 | 小红书/抖音/微博/X/Reddit/公众号/新闻/网页搜索/评论区 |
| 情感 | 正面/负面/中性/混合；评论区可用细分：期待/焦虑/观望/负面/玩梗 |
| 类型 | 官方/KOL/UGC/媒体/评论 |
| 互动 | 赞/评/转等，无则 `-` |
| 采集方式 | 浏览器/搜索/抓取 |

可选扩展：`parent=`（评论所属主内容 id）、`kol_type=`、`sentiment_detail=`。

### 去重规则

- 去重键：`source + content_id`；无 content_id 时用 `url`；再无则用规范化正文前 120 字的 SHA1 前 12 位。
- 同一轮内重复 → 丢弃；跨轮重复但互动量显著上升（≥50%）→ 追加一条并标注 `boosted`。
- 禁止用旧数据冒充新数据；主源失败记入「数据说明 · 已知缺口」。

## 增量读写与上下文预算

| 动作 | 策略 |
|------|------|
| 每轮开始读什么 | front matter +「话题摘要」（含活跃预警行）+「演变」最近 2–3 个节点；需要对比原始证据时再定点读数据条目，禁止全文吸入 |
| 每轮写什么 | 追加本轮数据条目、演变节点、信号；刷新 front matter `updated_at/rounds`；重写「话题摘要」；若 `dashboard: true` 同步 `dashboard/data.js` |
| 摘要长度 | 话题摘要 ≤ 15 行；单轮演变 summary ≤ 5 句 |
| 归档 | research.md > 约 200KB 或 rounds > 40 时：将早期数据条目剪切到同目录 `archive/R{n}-{date}.md`，正文保留指针与演变节点 |
| 单轮上下文预算 | 采集原文 + 分析输出合计控制在宿主单轮可读范围；超额时先出「一页摘要 + 盘点 + 缺口」，细节下轮补 |

## 报告三层

| 层 | 给谁 | 内容 | 时机 |
|----|------|------|------|
| 一页摘要 | 决策者 | 当前态势 / 本轮关键变化 / 预警 / 建议，1 页内 | 每轮默认 |
| 标准报告 | 执行 | 下方必备章节 | 每轮 |
| 危机快报 | 危机时 | 事件 / 证据 / 影响 / 处置建议 / 对外口径，10 分钟读完 | 红/橙预警触发时 |

### 标准报告章节

| 章节 | 内容 | 必备程度 |
|------|------|----------|
| 一页摘要 | 态势/变化/预警/建议 | 必备 |
| 本轮分析逻辑 | 为何选这些维度、基准、样本量 | 必备 |
| 本轮变化 | vs 上轮 diff：数据量、指标、新信号、新疑点 | 必备 |
| 核心发现 | 有证据的具体问题 | 必备 |
| 意味着什么 | 解读原因与影响 | 必备 |
| 建议怎么做 | 按优先级 | 必备 |
| 各平台评论区总结 | 每源一节，见模板 | 必备 |
| 信号与建议 | 按严重度 | 必备 |
| 舆情风险矩阵 | 概率×影响×预案 | 必备 |
| 竞品对比 | SoV/倾向/维度 | 按需 |
| 叙事主导权 | 三方占比与风险 | 按需 |
| 热点发酵预测 | 结论+触发+跟踪指标 | 推荐 |
| 数据附录 | 原始链接、Fact Check、时间戳 | 必备 |

空模块直接省略，不写「无数据」。

## 预警输出（结构化）

仅输出文本/JSON，由宿主决定是否推送。**skill 本身不发 Webhook、不写企业微信/飞书。**

预警 `type` 与分析阶段「信号」`type` 是两套枚举：信号描述数据变化，预警描述对外动作级别。映射示例见 `metrics.md`。

```json
{
  "severity": "red|orange|yellow|blue",
  "type": "volume_spike|negative_surge|new_keywords|kol_negative|competitor_shift|emotion_turn",
  "indicator": "负面占比 8%→23%（n=186）",
  "evidence": ["https://…"],
  "sla": "2小时|当天|1-3天|持续观察",
  "recommended_action": "…"
}
```

| 级别 | 含义 | SLA |
|------|------|-----|
| 红 | 不处理有实质损失 | 2 小时 |
| 橙 | 可能升级 | 当天 |
| 黄 | 需关注 | 1–3 天 |
| 蓝 | 记录观察 | 持续 |

## 危机处置闭环

```
红/橙预警 → 危机快报 → 处置建议（含对外口径） → 预案沉淀 → 72h 复盘
```

- 预案写入 `## 预案库`（追加）。
- 复盘：事件后约 72h 再采一轮，验证负面是否回落/叙事是否转移，更新预案有效性。
