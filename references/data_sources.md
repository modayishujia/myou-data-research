# 数据源与采集（Data Sources）

渠道优先级、动态选源、降级链、平台要点、评论区分层采样。场景链路见 `scenarios.md`，指标与标签见 `metrics.md`。

## 采集渠道与降级链

```
具备页面控制能力的浏览器工具（复用已登录会话，首选）
  → websearch（公开内容）
    → webfetch（指定 URL / 搜索结果页）
      → 该源标注「采集缺口」，禁止用旧数据冒充
```

| 渠道 | 适用 | 说明 |
|------|------|------|
| 浏览器工具 | 小红书/抖音/微博/X 等需登录态平台 | 搜索、进详情、采评论；环境内有多个可用工具时择一 |
| websearch | 新闻、公众号、研报、公开网页 | 限定时间窗 |
| webfetch | 指定 URL 全文、结果页 | 配合 websearch |

采集方式标签（`collection_method`）：

| 值 | 中文显示 |
|----|----------|
| 浏览器控制 | 浏览器 |
| websearch | 搜索 |
| webfetch | 抓取 |

## 数据源动态选择

采集前按话题特征匹配优先级；话题演变或主源失败时切换/补源，不固定同一套。

| 话题信号（命中任一） | 首选源 | 辅助源 | 说明 |
|----------------------|--------|--------|------|
| 国内大众消费 / 品牌口碑 / 产品发布 | 小红书、抖音 | 微博、公众号、新闻 | 评论区为重点 |
| 出海品牌 / 海外市场 / 全球事件 / 海外首发 | X、Reddit | 新闻 | 话题标签 + 转发链 |
| 技术 / 开发者 / 开源 / AI / 加密 | Reddit、X | 新闻（HN 可经 websearch） | 深度讨论在海外社区 |
| 金融 / 上市公司 / 交易 | 新闻、雪球/东财（websearch） | X | 时效与公告校准优先 |
| 泛文化 / 影视 / 游戏 / 热点事件 | 微博、抖音 | X、新闻 | 发酵快，注意时效窗口 |
| 争议 / 全球政策事件 | 新闻、X | Reddit | 关注首发源与立场分化 |

规则：

- 新话题启动时输出「源组合建议」并说明理由；既有话题每轮重估
- 主源采集失败 → 按降级链处理，用备选源补齐；禁止静默跳过
- 海外/技术话题至少保留 1 个国内源做对比；国内话题如涉海外反响，补采 X/Reddit

## 平台采集要点

### 小红书

- 搜索结果列表：标题、作者、时间、赞数；相关搜索词与筛选标签反映关注焦点
- 进入头部笔记详情页采评论区；注意算法干预（置顶官方、过滤负面）
- 优先已登录浏览器会话

### 抖音

- 搜索结果密度与头部视频互动（赞/评/转）反映参与深度
- 底部相关搜索词、筛选标签、AI 推荐摘要有分析价值
- 页面数字文本（如「475.6 万」）为互动量

### 微博 / X

- 优先站内搜索 / 话题页 / 热搜榜；记录首发账号 → 转发链 → 大 V 参与
- X 运算符：`from:`、`min_faves:`、`lang:`、`since:YYYY-MM-DD`
- 无浏览器能力时降级 `websearch site:weibo.com` / `site:x.com`，并标注降级

### Reddit

- 入口：`/search/?q=关键词&sort=top&t=…` 或具体 subreddit
- 记录帖子分数、评论数、subreddit、是否置顶/锁定
- 评论区树状：采顶级评论（含分数、时间）+ 高赞回复；注意折叠/删除
- 外文保留原文，分析结论用中文归纳
- 高频访问易被限；受限立即降级 `websearch site:reddit.com` 并标注「采样受限」
- 补充信号：downvotes/争议占比、subreddit 规模、crosspost 次数

### 公众号

- websearch（搜狗微信搜索或通用搜索）定位 → webfetch 抓全文
- 受限时降级通用搜索，记录媒体类型（官方/行业/自媒体）

### 新闻

- 定向检索并限定时间窗；重点报道抓全文
- 记录媒体权威性：央媒 / 地方 / 行业 / 自媒体
- 报道时间与社媒发布时间分开记录

## 评论区分层采样（必选）

对每个已启用数据源执行：

1. 取该话题下互动量 **Top 5–10** 内容
2. 每条内容抽 **15–30** 条评论，优先级：高赞 → 最新 → 争议/分歧
3. 汇总为该平台的「评论区总结」（模板见 `templates.md`）
4. 报告中必须写明：`样本量 n=…，来自 … 条内容，时间范围 …`
5. **n < 30**：只做定性观察，不输出百分比
6. 某内容无法采评论：标注缺口，不跳过平台总结

禁止「每内容 50–100 条 × 每平台」这类超出模型单轮可执行量的采样。
单轮平台评论总量目标约 80–200 条（可按平台数与内容数调整）。
某条内容互动异常高或出现新叙事时，该条可加采至约 50 条。

详细阈值与 KMI 见 `metrics.md`。
