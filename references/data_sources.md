## KMI（关键监测指标）详细计算

### 正面情绪占比
- **公式**: 正面评论数 / 总采样评论数
- **健康**: >70%
- **预警**: <50%
- **正面判定**: 包含"期待"类关键词（等不及/必买/心动/冲/太香了/绝了）

### 负面情绪占比
- **公式**: 负面评论数 / 总采样评论数
- **健康**: <15%
- **预警**: >25%
- **负面判定**: 包含"负面"类关键词（割韭菜/不值/太贵/失望/不如买 XX）

### 价格焦虑指数
- **公式**: 价格相关负面评论 / 总价格评论
- **健康**: <30%
- **预警**: >50%
- **价格评论识别**: 包含"价格/多少钱/贵/便宜/值不值/性价比"等关键词

### 疲劳指数
- **公式**: "挤牙膏/什么时候"类评论的增长率
- **健康**: 稳定或下降
- **预警**: 连续 3 天增长
- **疲劳词**: 挤牙膏/什么时候/还不发布/等太久了/遛粉

### KOL 正面率
- **公式**: 正面 KOL 数 / 已发声 KOL 总数
- **健康**: >70%
- **预警**: <50%
- **判定**: KOL 发布的内容整体态度为正面

### 竞品对比负面率
- **公式**: 竞品对比中"竞品更好"的占比
- **健康**: <30%
- **预警**: >50%
- **判定**: 对比讨论中用户倾向竞品的比例

## 情绪分类标准（5 类）

| 情绪类型 | 关键词特征 | 示例表述 |
|----------|-----------|----------|
| 期待 | 等不及/必买/心动/冲/太香了 | "这配置太香了，等上市" |
| 焦虑 | 价格/什么时候/等太久了/挤牙膏 | "到底多少钱，别挤牙膏了" |
| 观望 | 再看看/等等党/对比一下/不急 | "等实车到店再决定" |
| 负面 | 割韭菜/不值/太贵/失望/翻车 | "这价格不如买 XX" |
| 玩梗 | 哈哈哈/笑死/绝了/绷不住 | "雷总又来卖房了" |

## KOL 分类框架

| 类型 | 特征 | 适用场景 | 风险等级 |
|------|------|----------|----------|
| 品牌专属型 | 内容 100% 围绕单一品牌 | 发布前造势/情报释放 | 低 |
| 全品类测评型 | 覆盖所有品牌，以数据说话 | 发布后口碑/中立背书 | 低 |
| 平台级媒体 | 官方媒体账号，专业团队 | 大众覆盖/权威背书 | 低 |
| 辣评/观点型 | 以个人观点/争议性内容为主 | 话题引爆（双刃剑） | 高 |
| 车友会/社区型 | 车主自发组织的社区账号 | UGC 内容/车主证言 | 低 |

## 风险评估矩阵

| 评估维度 | 问题 | 输出 |
|----------|------|------|
| 概率评估 | 该风险发生的可能性有多大？ | 高/中/低 |
| 影响评估 | 若发生，对品牌的影响有多大？ | 极高/高/中/低 |
| 触发条件 | 什么情况下会触发该风险？ | 具体触发条件描述 |
| 预警指标 | 如何提前监测到风险信号？ | 可量化的监测指标 |
| 应对预案 | 风险发生后如何应对？ | 响应时间+应对措施 |
| 跟踪频率 | 多久监测一次？ | 每日/每 12 小时/每小时 |

## 预测框架

| 预测类型 | 方法 | 输出格式 |
|----------|------|----------|
| 热点发酵预测 | 基于当前数据趋势+历史规律 | 预测结论+触发条件+背景意义+跟踪指标 |
| 风险演变预测 | 基于风险当前状态+外部变量 | 当前状态+预测变化+管控动作+跟踪频率 |
| 竞品动态预测 | 基于竞品历史动作+行业节奏 | 预测竞品可能动作+应对预案 |
| 用户行为预测 | 基于用户当前情绪+决策链路阶段 | 预测用户下一步行为+品牌应对策略 |

## 抖音搜索热度分析要点

- **搜索结果密度**: 搜索某关键词返回的视频数量和质量 → 密度高=话题热度高
- **头部视频互动**: 搜索结果前 10 条视频的点赞/评论/分享 → 互动量级反映用户参与深度
- **相关搜索词**: 搜索结果页底部的推荐搜索词 → 反映用户延伸需求
- **筛选标签**: 搜索结果页的筛选维度 → 反映用户关注维度的优先级排序
- **AI 推荐摘要**: 抖音 AI 生成的搜索摘要 → 反映平台算法对内容的理解和聚合方向

## 小红书 / 抖音 采集结构要点

- **小红书笔记列表**：页面中笔记卡片节点（如 `section.note-item`），其文本含标题、作者、时间、赞数；进入详情页后评论区节点（class 含 `comment`）可提取评论。
- **抖音搜索结果**：视频标题、互动数据位于列表项节点；热门标签反映用户关注焦点；`StaticText` 中的数字（如「475.6 万」）为互动量。
- 注意识别算法干预痕迹（置顶官方内容、过滤负面评论），优先使用已登录浏览器会话以保证数据完整性。

## 微博 / X（Twitter）采集要点

- **优先**：浏览器控制工具（如 Kimi WebBridge）进站内搜索/话题页/热搜榜，复用已登录会话；其次浏览器自动化会话
- **内容抽取**：微博正文/转发/评论/超话；X 推文卡片（发布时间/作者/互动数）；搜索建议标签与热门话题排名
- **传播路径**：记录首发账号 → 转发链 → 大 V 参与 → 热搜位变化；评论采集同 Step 4 流程
- **降级**：websearch `site:weibo.com` / `site:x.com` 引用公开链接与摘要，并标注降级

## 公众号 / 新闻采集要点

- **公众号**：websearch（搜狗微信搜索/通用搜索）定位文章 → webfetch 抓全文；注意频控，受限即降级通用搜索并标注
- **新闻**：websearch 定向检索（限定时间窗口）→ 重点报道 webfetch 全文；记录媒体权威性（央媒/地方/行业/自媒体）
- 新闻的「时间」是报道时间，与社媒发布/评论时间分开记录

## 浏览器采集降级链

```
浏览器控制工具（如 Kimi WebBridge，首选）
  → 浏览器自动化会话（复用已登录浏览器）
    → websearch / webfetch（公开内容，标注降级）
      → 该源标注「采集缺口」，禁止用旧数据冒充新数据
```

## 信号与建议框架

每轮分析输出信号，每个信号带建议，按严重度排列：

```markdown
### 信号与建议

| 严重度 | 信号类型 | 发现 | 建议 |
|--------|----------|------|------|
| 严重 | 热度飙升 | 具体发现描述 | 具体建议 |
| 高风险 | 情感转向 | 具体发现描述 | 具体建议 |
| 中等 | 关键词涌现 | 具体发现描述 | 具体建议 |
```

### 信号严重度定义

| 级别 | 含义 | 响应时间 | 示例 |
|------|------|----------|------|
| 严重 | 需要立即关注，不处理会有实质损失 | 当天 | 负面舆情爆发、数据异常、重大风险事件 |
| 高风险 | 需要持续监控，可能升级 | 1-3 天 | 情感转向、叙事变化、竞品动态 |
| 中等 | 值得关注，暂不需行动 | 持续 | 关键词涌现、趋势变化、潜在风险萌芽 |
| 低 | 信息记录，无需行动 | 记录 | 常规数据变化、已知趋势延续 |
